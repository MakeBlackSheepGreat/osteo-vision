# 平台集成规则

本规则用于新增或调整平台能力，确保数据契约、运行配置、服务接口、前端工作流和证据输出保持一致。所有改动都应以可复现的工程行为为依据，并保留医学安全边界。

## 适用范围

- 新增数据输入、格式适配或数据集清单。
- 新增分析任务、模型适配器或推理流水线。
- 调整前后端接口、病例状态或导出格式。
- 新增运行配置、离线发行内容或质量门。

## 集成原则

1. 输入、任务、模型、结果和复核状态通过版本化契约传递。
2. 领域差异进入 `configs/`、适配器或专用流水线，共享层保持可复用。
3. 文件路径只允许解析到受控数据根，禁止写入开发机绝对路径。
4. 每个输出保留来源、参数、模型身份、时间戳、哈希和失败原因。
5. GPU 加速只在运行时预检通过后启用；驱动、显存或依赖异常时回退 CPU，并写入可追溯状态。
6. 真实患者数据遵循脱敏、最小保留和批次准入要求，隔离数据不得进入病例或训练清单。
7. 临床输出保持医生复核与非诊断定位，缺少证据时执行安全回退。

## 推荐实现边界

| 层 | 入口 | 责任 |
|---|---|---|
| 配置 | `configs/tasks/`、`configs/inference/` | 声明输入格式、任务参数、模型和运行策略 |
| 数据 | `osteo_vision_core/datasets/` | 清单、来源、分组、准入和路径校验 |
| 预处理 | `osteo_vision_core/preprocess/` | 解码、质量检查、配准、归一化和尺寸约束 |
| 模型 | `osteo_vision_core/models/` | 适配器、运行时预检、阈值和安全回退 |
| 服务 | `backend/osteo_vision_api/` | API、病例、任务、复核、导出和审计日志 |
| 前端 | `frontend/src/` | 输入、状态、结果、复核和可见错误反馈 |
| 证据 | `tools/`、`research/reports/release/`、`artifacts/` | 生成索引、报告、截图、哈希和运行记录 |

## 最小验收

每次集成至少补充以下检查：

- 合法输入能够完成端到端流程，输出契约字段齐全。
- 缺失、越界、损坏、低质量或来源不可信时给出可读错误并安全降级。
- GPU 与 CPU 路径都能启动，日志记录实际设备和回退原因。
- 前端操作有真实反馈，任务进度、失败原因和恢复入口可见。
- 单元、契约或 smoke 测试覆盖新增行为；必要时补充桌面或浏览器验收。
- 生成文件进入受控目录，manifest 与 SHA256 可重建。

## 交付说明

变更完成后更新对应 README、`docs/` 或 `research/reports/release/` 入口，说明运行命令、输入边界、验证状态和已知限制。避免将一次性机器状态、临时路径或未经验证的临床结论写入当前文档。
