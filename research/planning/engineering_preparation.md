# 前期工程准备路线图

更新时间：2026-06-12

归档说明：本文记录 2026-06-12 的前期准备状态。现行平台目标、目录与验收口径以根目录 `README.md`、`README_CN.md` 和 `research/reports/planning/osteo_vision_platform_target_zh.md` 为准；文中旧目录与一次性生成脚本已经清理。

## 目标边界

当前阶段的目标是搭建可演示、可复现、可接入真实样本的工程骨架。不要在没有真实术中白光/ICG样本和医生标注前承诺临床级诊断性能。

推荐 MVP 路线：

1. 赛点一：白光/荧光图像配准、伪彩叠加、强度曲线、截图/视频导出。
2. 赛点二：交互式 ROI + 弱 AI 热图平台能力，先用公开牙科/CBCT数据做预训练或演示。
3. 赛点三：病例包导出、DICOM secondary capture 或结构化报告雏形。

## 第一阶段任务

### P0：仓库可信度修复

1. 统一清单和报告中的数量口径。
2. 修正“PDF 全部附有”等与本地状态不一致的表述。
3. 将 `output/literature/dataset_inventory.csv` 转为 UTF-8。
4. 明确哪些代码能直接跑，哪些只作为文献论证。

验收标准：

- 自检脚本不再报告编码错误。
- 报告中的论文、数据集、PDF状态与本地文件一致。
- README 中的项目结构与真实目录一致。

### P0：数据落地

1. 下载或申请 D024 DentVoxel。
2. 下载或申请 D025 牙源性病灶 CBCT+病理。
3. 注册并下载 D036 ToothFairy2。
4. 下载 D044 FGS ICG 荧光手术视频。
5. 视时间补充 D042 MODID 多光谱口腔数据。

验收标准：

- `datasets/` 下存在对应目录。
- 每个数据集目录包含来源说明、许可/引用信息、原始文件校验记录。
- 至少一个数据集完成样例读取和可视化预览。

### P1：平台工程骨架

建议先做一个离线 Gradio 平台验证入口，输入白光图、荧光图或视频帧，输出：

- 配准后叠加图
- 伪彩增强图
- 荧光强度热图
- ROI 区域统计
- 演示导出图或视频

验收标准：

- 不依赖训练即可演示赛点一。
- 所有输入输出样例可复现。
- 后续能替换为真实显微镜数据。

### P1：AI 基线

先以 `nnU-Net` 或轻量 U-Net/MedSAM 交互式分割作为主线。EGNet、FRS Loss 暂列为增强模块，等源码和依赖补齐后再纳入实验。

验收标准：

- 有一个明确的数据格式转换脚本。
- 有一个最小训练/推理命令。
- 有 Dice/IoU/HD95 或至少 Dice/IoU 的评估脚本。

## 决策门槛

继续投入赛点二强化的前提：

- 至少拿到 10-30 例脱敏术中白光/ICG 图像或视频。
- 至少有医生标注的坏死骨、疑似病灶边界或保留区。
- 能确认企业显微镜导出的图像/视频格式和帧率。

如果拿不到真实样本，赛点二应降级为辅助演示，不作为核心竞争力承诺。
