### 7.1.2 端到端演示闭环

端到端演示闭环以官方 4K JPEG/MP4 为主输入路径，串接以下阶段：

1. 录入脱敏病例并完成批次准入：记录机构授权、脱敏确认、用途范围、SHA256、可解码性、通道关系与同步配对；只有通过准入的文件可登记为病例输入，被隔离的文件仅保留原因码，新准入样本默认标记为"待复核""无标签""训练准入否"。
2. 导入 4K JPEG/MP4，由输入准入服务校验通道关系与同步配对，进入分析流水线。
3. 自动执行配准、归一化、伪彩、融合、质控、ROI 定量；4K JPEG 双通道触发白光/ICG 配对分析，MP4 进入关键帧分割与连续帧快速输出实时叠加。
4. 4K 分块关键帧分割输出骨面门控掩膜、荧光信号掩膜、边界风险掩膜、不确定性掩膜四类掩膜与骨活性连续谱；其中骨面门控掩膜在医生 ROI 或提示辅助复核生成前仅记录为待复核/不可用，不作为骨面真值。
5. 医生复核、人工标注、版本审计、双签晋级；通过或修改的样本进入高权重训练清单，驳回样本默认作为负例或错误分析数据，复核权重按通过 4.0、修改 4.0、驳回 0.5、待复核 1.0 派生。
6. 导出结构化数据 + 量化表格 + Markdown + DICOM SC + ZIP 证据包，含截图、掩膜、量化结果与报告。
7. 三维工作台 L1 静态仿体配准与 L2 离线动态 AR 进入独立前端子页面承载，与病例工作台共享当前病例、关键帧候选区、配准状态、坐标变换、模型来源与医生复核数据。

可重放证据产物位于本机 Git 忽略的运行产物目录下，包含运行配置、四类掩膜、关键帧截图、量化表格与运行日志；按规则不进入版本库，评审可由本机重放命令复现。一键启动入口位于仓库最外层，经严格运行预检与模型预热后拉起前后端，后端在固定端口上提供服务，推理核心由模型预热调用完成预热，并暴露预热接口供前端在启动实时分析前显式触发。

### 7.1.3 设备解耦与清单接入

平台软件保持设备解耦，倍率、工作距离、相机标定、坐标变换与位姿记录通过离线清单或人工元数据接入，不依赖企业私有接口。推理运行配置在每个模型项设置设备策略为自动，无 GPU 时仍可工作，仅推理延迟上升；当前以 NVIDIA GeForce RTX 5060 Laptop GPU 验证基线，4K 分块推理峰值显存约 724 MB，低于 2048 MB 显存门控上限。

核心热路径优化已落地并完成回归测试，关键加速比如下：

| 热路径 | 加速比 |
|---|---:|
| 1024 连通域候选统计 | 31.91× |
| 3840×2160 质量评估 | 4.56× |
| 10,000 位姿最近邻批量查询 | 324.87× |
| 1,000 任务记录缓存查询 | 5.64× |

实时帧鲁棒性方面，实时帧服务实现请求体前容量准入、格式/尺寸门控、取消传播、错误码透传与输出路径约束；每病例有界保留（默认 120 帧，可配 1–1000）；临时目录生成 + 原子提交，Windows 目录替换在 10/25/50/100/200 ms 间隔上有界重试；150 帧压力回归通过。每帧唯一证据路径由前端生成，避免浏览器复用首帧图片缓存导致画面停留在第一帧。

| 层级 | 实现方式 | 工程验证状态 |
|---|---|---|
| L0 失效回退与坐标契约 | 坐标契约模块 | 已实现（任一门控失败 → 导航就绪标记为否、导航级别降为 L0、回退模式为未配准三维参考） |

## 7.3 临床应用：说明对传统临床诊疗流程的改进

### 7.3.1 传统流程

颌骨骨髓炎的传统临床诊疗流程通常包含以下阶段：

1. **术前影像**：X 线、CBCT、MRI 用于评估病灶范围与死骨分布，但影像与术中实际情况存在时间差与体位差。
2. **经验性术中判读**：术中由医生依靠肉眼、触诊、术中 X 线判读死骨与活性骨边界，判读高度依赖术者经验。
3. **肉眼/触诊定边界**：清创边界以肉眼可见的死骨颜色、质地与出血情况为主要依据，缺乏可量化的活性边界信号。
4. **清创与序列治疗**：依据上述判读执行清创，术后通过抗生素、序列治疗与影像随访确认效果，复发率与边界判读准确性高度相关。

传统流程的核心痛点包括：影像与术中实时性脱节、死骨与活性骨边界依赖经验、缺乏定量与可复核指标、难以支持术中即时决策。

### 7.3.2 改进后的流程

平台软件在不改变医生最终判读权的前提下，对传统流程进行工程化改造，改进后的流程如下：

1. **术前影像 + 病例准入**：术前 CBCT/STL 通过三维工作台导入并完成批次准入，记录机构授权、脱敏确认、用途范围、SHA256 与通道关系；只有通过准入的文件进入病例档案。
2. **4K 术中视频流**：术中显微镜输出的 4K MP4 视频流（或成对 JPEG）作为一级可见输入方式导入主工作流，原始播放显示在四宫格"视频流输入"视口。
3. **白光/ICG 配准融合**：双通道融合模块完成十步融合链，自动执行配准、归一化、伪彩、融合、质控与 ROI 定量，融合图、热图、归一化图在四宫格输出区呈现。
4. **AI 候选区 + 风险/不确定性提示**：4K 分块关键帧分割与连续帧快速输出实时叠加输出骨面门控掩膜、荧光信号掩膜、边界风险掩膜、不确定性掩膜四类掩膜与骨活性连续谱，作为医生术中参考信号。
5. **医生复核定边界**：医生在人工标注页与复核工作台完成标注、通过、修改或驳回，双签晋级与哈希链审计落地；通过或修改的样本进入高权重训练清单。
6. **证据包回灌**：导出结构化数据 + 量化表格 + Markdown + DICOM SC + ZIP 证据包，回灌至训练清单与多中心验证准备；三维工作台 L1/L2 工程验证作为术中参考延伸。

### 7.3.3 改进点对照

| # | 维度 | 传统流程 | 改进后的流程 | 改进性质 |
|---|---|---|---|---|
| 1 | 实时性 | 术前影像与术中存在时间差与体位差 | 4K 术中视频流实时进入四宫格，连续帧快速输出实时叠加（P95 176.457 ms） | 工程化改进（非临床性能） |
| 2 | 边界判读 | 肉眼/触诊经验判读，依赖术者经验 | AI 候选区 + 边界风险掩膜/不确定性掩膜风险提示 + 医生复核双签 | 流程改造，医生复核为最终判读依据 |
| 3 | 量化 | 缺乏可量化指标 | 荧光强度、灌注/活性比值、边界风险、骨活性连续谱、ROI 时序曲线 | 量化能力已落地，目标域指标待补 |
| 4 | 可追溯 | 术中判读无结构化记录 | 批次准入、SHA256、复核状态、哈希链审计、证据包 | 已实现 |
| 5 | 三维延伸 | 术前 CBCT 静态参考，无术中对应 | CBCT/STL 五路径建模 + L1 静态仿体配准 + L2 离线动态 AR；导航就绪标记为否，保持未配准参考 | 契约已定义并完成工程验证，真实术中导航待补 |

上述改进点对应的工程实现状态明确区分如下：

- **已实现**：批次准入与 SHA256、四宫格主工作流与四类掩膜输出契约、连续帧快速输出实时叠加、医生复核双签与哈希链、证据包导出（结构化数据 + 量化表格 + Markdown + DICOM SC + ZIP）、L0 失效回退与坐标契约、L1/L2 工程验证。
- **契约已定义但未完全实现**：骨面门控掩膜在医生 ROI 或提示辅助复核生成前仅记录为待复核/不可用；提示可分割模型仅作为提示回退契约工具，不声称真实 MedSAM2 模型权重推理。
- **待实现**：真实目标域 ICG 颌骨骨髓炎 MP4/JPEG 像素级医生标注（当前记录数为 0）、目标域三分类性能验证、真实术中导航（导航就绪标记当前保持为否）、多中心概率校准与亚组审计、注册合规与产业化路径。

### 7.3.4 临床落地边界

平台软件定位为研发验证版平台软件，所有临床应用改进均以工程可核验为限。医院合作方面，当前医生合作单位为绵阳市第三人民医院头颈部颌面甲状腺科，现场设备为医院自有设备，与成都赛题方的设备属于两套独立设备；医院设备确认可导出 JPG 与 AVI，并提供黑白荧光和伪彩显示模式，原彩或独立白光模式的导出能力仍待医院设备侧确认；平台为医院 AVI 建立受控转码流程，保留原始 AVI、SHA256、编解码参数、转码日志与原始文件到 MP4 的对应关系。医院设备的格式、显示模式、参数与接口不推定为赛题方设备能力，两类设备的资料、样本、接口与验证结果分别记录设备来源、准确型号、固件版本与采集配置。近期医院可采集的 ICG 病例以软组织手术为主，颌骨相关病例时间不确定，软组织 ICG 数据作为设备、信号与时序工程验证域，颌骨骨髓炎或颌骨相关 ICG 作为目标域，两类数据分层保存、分组评估，不混为目标域训练数据或颌骨临床性能证据。
