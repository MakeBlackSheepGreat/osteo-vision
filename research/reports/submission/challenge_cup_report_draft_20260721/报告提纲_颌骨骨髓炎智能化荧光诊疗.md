## Cap 1 项目背景与临床需求

### 1.1 颌骨骨髓炎概述
- 流行病学与分型：急性 / 慢性 / 继发性 / 药物相关性（MRONJ）等
- 发病机制：感染、血供破坏、药物相关骨坏死、外伤、放射性因素
- 临床表现：疼痛、瘘管、死骨形成、感觉异常、面部畸形
- 病理过程示意（Fig 1：物理/病理过程示意图，含分期与活性边界）
- 现有治疗路径：抗生素、清创、血供重建、序列治疗
- 核心临床痛点：病灶边界不清、过度清创或清创不足、复发率高、术中实时判读缺位

### 1.2 当前疾病诊疗方式与不足
- 传统术前评估：影像学（X 线 / CT / MRI）、活检
- 传统术中判读：肉眼、触诊、术中 X 线
- 存在的主要问题（1–4 任选展开）：
  1. 影像与术中实时性脱节
  2. 死骨与活性骨边界依赖经验
  3. 缺乏定量与可复核指标
  4. 难以支持术中即时决策

### 1.3 国内外技术研究现状
- 荧光造影与术中导航
  - ICG 在外科的临床应用与文献证据
  - ICG 现有不足：非特异性（血流/灌注主导）、早期信号弱、坏死—活性区分有限
  - 替代/增强方向：四环素类（骨结合）、自体荧光、Evans blue（血管通透性）
- 医学图像智能分析
  - 多模态融合：结构 + 功能
  - 模型演进：CNN → Transformer → Mamba 等
  - 任务演进：分类 → 检测 → 分割 → 不确定性提示
- 当前空白：术中实时性不足、目标域数据稀缺、医生交互闭环弱
- 本项目切入点：构造"造影剂设计 + 多模态融合 + AI 判读 + 医生复核"的完整方案

### 1.4 项目边界与免责
- 范围、不可声称内容、医生复核边界、目标域数据缺失声明

## Cap 3 荧光造影剂设计

### 3.1 设计目标
- 颌骨骨髓炎术中场景特点：出血、灌注、坏死信号并存；工作距离与放大倍率可变；要求快速、特异、低毒
- 目标分解：提升骨面/死骨/活性区信号对比；与 ICG 联合无通道串扰；与显微荧光成像系统激发/发射匹配

### 3.2 设计思路
- ICG 既有方案的不足：非特异性、染色持续时间与对比度有限、死骨/活性骨区分有限
- 通过文献查阅 + 化合物特性分析提出候选
  - 候选 A — Evans blue：血管通透性差异
  - 候选 B — 四环素类：骨结合特性（猜想研究方向）
- 与 ICG 联合使用思路（灌注层 + 骨结合层互补）

### 3.3 显微适配性与工程替代证据
- 激发/发射波长与显微镜通道匹配
- 术中工作距离与放大倍率下的对比度
- 替代证据来源：公开文献、类体实验数据、仿真
- 边界声明：造影剂实物合成与湿实验验证不在本项目交付范围；当前以文献证据 + 工程替代方案支撑后续验证

## Cap 7 工程实现与临床应用方案

### 7.1 软件系统架构图（Fig）
- 平台软件三层：荧光分析 / AI + 医生判读 / 结果输出
- 端到端演示闭环：4K MP4/JPEG → keyframe 分割 → 伪彩/叠加 → 医生复核 → 证据包
- 设备解耦：倍率、工作距离、标定通过 manifest 接入

### 7.2 界面（Fig）
- 主工作流界面：视频流输入、融合图、热图、归一化/分割结果四宫格
- 关键功能模块展示
  - 4K 视频流播放与同步分析
  - 白光 / ICG 配准与伪彩叠加
  - AI 候选区、风险提示、不确定性可视化
  - 医生复核（标注 / 通过 / 修改 / 驳回）
  - 证据包导出（截图、mask、JSON、PDF）
- 次级界面：数据准入、病例档案、医生复核工作台、三维导航
- 主题切换、空状态、桌面宽屏布局说明

### 7.3 临床应用：说明对传统临床诊疗流程的改进
- 传统流程：术前影像 → 经验性术中判读 → 肉眼/触诊定边界 → 清创
- 改进后的流程：术前影像 + 病例准入 → 4K 术中视频流 → 白光/ICG 配准融合 → AI 候选区 + 风险/不确定性提示 → 医生复核定边界 → 证据包回灌
- 改进点对照
  1. 实时性：术中实时信号替代术前影像延迟
  2. 边界判读：从经验判读过渡到 AI 候选 + 医生复核
  3. 量化：引入荧光强度、灌注/活性比值、边界风险
  4. 可追溯：批次准入、SHA256、复核状态、证据包
  5. 三维延伸：CBCT/STL 配准与术中参考
- 边界声明：研发验证版定位、医生复核为最终判读依据、非自动确诊

## Cap 8 创新性与可行性

### 8.1 创新点
- 技术层：候选造影剂组合（ICG + Evans blue / 四环素类猜想）+ 多模态融合算法 + 多模态 AI 判读模型
- 工程层：设备解耦、批次准入、医生复核闭环、证据包
- 临床层：术中实时性、边界风险提示、医生交互判读流程改造

### 8.2 可行性
- 技术可行性：关键算法在公开/代理数据上的可复现结果；与现有显微成像系统的输入边界兼容
- 工程可行性：平台软件三层闭环已在比赛版落地；端到端演示闭环可重复运行；配置、checkpoint、manifest、报告齐备
- 临床可行性：保留医生复核边界、不替代医生判断；与医院 1 现有流程可对接（流程改进清单）
- 可推广性边界：当前证据以公开/代理数据为主，目标域数据待补；多中心、概率校准、亚组审计、注册合规纳入后续规划
