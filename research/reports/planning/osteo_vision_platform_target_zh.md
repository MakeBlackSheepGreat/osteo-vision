# 颌骨骨髓炎软件平台目标说明

生成日期：2026-06-15

## 1. 文档目的

本文用于固定当前项目的目标描述，作为后续产品设计、前后端拆分、算法接入、比赛答辩材料和代码实现的共同参照。

本文件承载较完整的平台构思；`AGENTS.md` 只注入长期稳定的开发边界和赛题目标，不注入仍可能微调的界面细节、模型路线和数据集选择。

## 2. 赛题要求总结

完整赛题原文要求围绕颌骨骨髓炎术中辅助决策，以荧光手术显微镜为核心应用平台，形成一套“新型荧光造影剂设计 + 多模态医学图像融合与处理 + AI 辅助显微成像判读”的技术方案。标准化输出、DICOM 和远程协作可作为软件平台扩展亮点，但不是完整赛题原文列出的核心答题要求。

根据赛题官方技术文档，设备侧已具备 4K 超高清影像摄录系统，分辨率为 3840x2160；影像通过 USB3.0 存储，图片和视频记录格式分别为 JPEG 和 MP4。因此本项目的软件输入边界应优先围绕 **4K MP4 视频流/上传文件** 与 **JPEG 图片上传** 设计，再兼容 PNG、TIFF、DICOM、NIfTI 等研究扩展格式。

完整赛题核心答题要求包括：

1. 新型荧光造影剂设计：面向颌骨骨髓炎病灶精准示踪，说明显微荧光成像条件下的示踪机理、靶向或选择性依据、必要实验或验证数据支持，以及与显微荧光成像系统的适配性。
2. 多模态医学图像融合与处理：对白光通道、荧光通道等多源图像进行获取、配准、融合、伪彩增强、热图展示和定量分析，并说明实时显示或辅助导航应用。
3. AI 辅助显微成像判读：基于目标检测、分割、分类或量化模型，提示疑似坏死骨、异常灌注区、边界风险区或需要医生复核的区域，并以叠加提示、风险标注或决策辅助形式呈现。

本项目不应被设计成单一医学影像模型展示，也不应被简化成普通图片上传工具。比赛作品需要体现完整软件链路、医学场景边界和可复核结果。

## 3. 项目最终目标

项目目标是做成一个面向颌骨骨髓炎术中场景的纯软件辅助判读平台，同时为完整参赛方案中的造影剂设计提供成像、量化和验证支撑。当前版本优先支持官方设备可输出的 4K MP4 视频文件、视频流预览和 JPEG 图片上传，并使用离线图片、同步帧序列、模拟视频和公开数据完成演示；未来可扩展到真实荧光手术显微镜输出、真实脱敏病例和院内协作场景。

推荐中文定位：

**颌骨骨髓炎术中荧光辅助判读软件平台**

推荐英文定位：

**ICG-Fluorescence Surgical Interpretation Workbench for Jaw Osteomyelitis**

比赛展示表达：

**基于白光/ICG 双通道影像的颌骨骨髓炎术中边界风险提示与病例报告软件**

## 4. 固定平台边界

现阶段只关注双通道数据进入软件之后的后三层：

1. **荧光分析层**：对白光/ICG 双通道图像、帧序列或视频片段进行配准、伪彩、融合、归一化、质控、ROI 定量和时间序列分析。
2. **AI 与医生交互判读层**：给出候选区域、边界风险、不确定性提示和关键帧建议；医生可以调整阈值、手动画 ROI、修改 AI 建议并记录复核状态。
3. **结果输出层**：生成关键截图、结构化 JSON、量化 CSV、Markdown/PDF 报告、病例证据包，后续扩展 DICOM secondary capture、DICOM SR 和远程协作。

本阶段暂不纳入：

- 患者全流程管理。
- 医院 HIS/EMR/PACS 集成。
- 真实设备驱动和实时采集 SDK。
- 完整术前手术规划。
- 自动临床诊断。
- 多中心临床验证系统。

## 5. 医学逻辑边界

ICG 主要反映血流灌注、血管通透性和组织活性差异。它可以作为术中组织活性和灌注状态的参考信号，但不能作为颌骨骨髓炎特异性探针。

平台输出应定位为：

- 低灌注提示。
- 异常荧光增强提示。
- 可疑坏死骨候选区。
- 边界不确定区。
- 需要医生复核的区域。
- 病例级证据和量化记录。

平台输出应避免：

- 自动确诊骨髓炎。
- 自动决定切除边界。
- 替代病理、影像科或主刀医生判断。
- 在缺少真实术中白光/ICG 样本和医生标注时承诺临床级性能。

## 6. 真实软件使用场景

### 6.1 角色

- 主刀医生：确认边界、调整阈值、接受或修改 AI 建议。
- 术中助手：导入图像或帧序列、选择关键帧、补充术中备注。
- 科研人员：回看病例、导出证据包、做批量统计和模型评估。
- 平台管理员：配置模型版本、报告模板、导出格式和权限。

### 6.2 一次完整会话

1. 用户新建或打开脱敏病例。
2. 用户导入官方设备导出的 4K MP4 视频、实时视频流预览、JPEG 图片，或导入研究扩展格式下的白光图、ICG 荧光图、同步帧序列。
3. 系统执行质控，检查尺寸、通道匹配、过曝、欠曝、模糊、荧光弱信号和时间戳异常。
4. 系统生成白光图、荧光灰度图、伪彩热图、叠加图和阈值掩码。
5. 医生选择或绘制 ROI，系统计算 ROI 内荧光均值、最大值、p95、阳性面积、区域占比和背景比值。
6. AI 模块生成候选区域、低灌注风险图、高荧光风险图或边界不确定图。
7. 医生将候选区域标记为 `accepted`、`modified`、`rejected` 或 `review_required`。
8. 系统保存所有参数、图像、曲线、医生备注和复核状态。
9. 会话结束后导出报告、结构化结果、量化表和病例证据包。

### 6.3 界面形态

推荐目标界面采用前后端分离 Web 工作台：

- 左侧：病例列表、输入通道、文件状态、任务进度和历史结果。
- 中央：白光、荧光、叠加图三联视图，支持同步缩放、拖动、切帧和 ROI 操作。
- 右侧：阈值、透明度、色图、ROI 列表、AI 建议、医生复核状态和质控提示。
- 底部：时间轴、强度曲线、事件日志和导出入口。

比赛阶段可以使用 Gradio 快速承载核心流程；正式软件形态应逐步迁移到 Vue 前端和 Python API 后端。

## 7. 输入与输出

### 7.1 输入形态

第一阶段支持：

- 官方设备 JPEG 图片上传。
- 官方设备 4K MP4 视频文件上传。
- 单帧白光图像。
- 单帧 ICG 荧光图像。
- 可选元数据：曝光、增益、采集时间、给药后时间、设备信息。

第二阶段支持：

- 视频流预览或短片段采集。
- 白光帧序列。
- 荧光帧序列。
- 同步时间戳。
- 短视频片段。

第三阶段支持：

- 设备导出的双通道或模式切换视频。
- 术前 CBCT/CT/全景片结果。
- 医生标注或历史复核结果。

### 7.2 输出形态

当前阶段输出：

- `overlay.png`：白光与荧光伪彩叠加图。
- `heatmap.png`：荧光热图。
- `normalized_fluorescence.png`：归一化荧光图。
- `roi_mask.png`：ROI 或候选区域掩码。
- `quantification.csv`：ROI 定量表。
- `report.json`：结构化结果。
- `report.md`：单病例 Markdown 报告。

后续扩展输出：

- PDF 报告。
- MP4 关键片段。
- ZIP 病例证据包。
- DICOM secondary capture。
- DICOM SR。

## 8. 核心能力模块

### 8.1 荧光分析模块

- 图像尺寸对齐。
- 白光/荧光配准。
- 荧光强度归一化。
- 噪声抑制。
- 过曝/欠曝提示。
- 伪彩热图。
- 白光叠加图。
- 阈值掩码。
- ROI 定量。
- 序列强度曲线。

### 8.2 AI 辅助模块

AI 模块优先承担辅助任务：

- 自动建议 ROI。
- 分割高荧光或低荧光区域。
- 提示疑似边界风险区。
- 生成不确定性热图。
- 选择关键帧。
- 检测低质量帧或伪影。

模型和数据集保持可变。nnU-Net、MedNeXt、U-Mamba、MedSAM、SAM2、YOLO、ConvNeXt、ViT 等都只能通过配置、适配器和实验报告进入，不在平台目标中写死。

### 8.3 医生交互模块

- 手动画 ROI。
- 调整阈值、透明度、色图和强度窗口。
- 接受、修正或排除 AI 候选区。
- 标记疑似坏死骨、疑似炎症、保留区和不确定边界。
- 添加备注。
- 保存复核状态。

### 8.4 报告模块

报告应包含：

- 输入文件摘要。
- 分析参数。
- 质控提示。
- 关键图像。
- ROI 定量结果。
- AI 候选区域状态。
- 医生复核记录。
- 研究原型免责声明。

## 9. 固定技术栈

正式平台技术栈：

- 前端：TypeScript + Vue 3 + Vite。
- 前端状态：Pinia。
- 前端路由：Vue Router。
- UI 组件：Element Plus 或 Naive UI。
- 图像交互：Canvas/WebGL。
- 曲线可视化：ECharts。
- 后端/API：Python 3.11 + FastAPI。
- AI 核心：PyTorch。
- 医学影像处理：OpenCV、SimpleITK、nibabel、pydicom。
- 数据处理：NumPy、pandas、scikit-learn。
- 配置：YAML。
- 测试：pytest。

临时演示技术栈：

- Gradio 可继续作为比赛快速演示和验证桥接层。
- Gradio 不作为长期正式前端形态。

## 10. 比赛版最小可信范围

为了控制复杂度，比赛版优先完成：

1. 官方 4K MP4/JPEG 输入接收、基本质控和关键帧抽取。
2. 单帧白光/ICG 双通道融合。
3. 小规模帧序列强度曲线。
4. ROI 手动画和阈值调节。
5. 低灌注/高荧光风险图。
6. AI 候选区演示。
7. Markdown、JSON、PNG、CSV 导出。
8. 可复核的病例证据包。

比赛版暂缓：

- 实时设备接入。
- 完整病例管理系统。
- PACS/HIS/EMR 集成。
- 自动诊断。
- 多医生在线协同。
- 大规模临床验证。

## 11. 工程落地路线

### V1：可演示闭环

- Gradio 或最小 Web 原型跑通双通道输入、融合、热图、ROI 统计和报告导出。
- 所有输出可复现。
- 报告保留免责声明。

### V2：前后端分离原型

- Vue 前端实现病例页、图像分析页和报告页。
- FastAPI 后端提供上传、分析、任务状态、结果查询和导出接口。
- 当前 Python 融合与量化能力迁移为后端服务。

### V3：AI 基线接入

- 通过 `src/models/adapters.py` 接入可替换模型。
- 通过 `configs/tasks/osteo_vision.yml` 和 `configs/inference/osteo_vision.yml` 管理任务契约与运行配置。
- D024/D025 等公开数据继续用于结构分割和病灶相关验证。

### V4：真实样本闭环

- 接入脱敏术中白光/ICG 样本。
- 接入医生标注或复核记录。
- 形成病例级证据链、失败样本记录和模型迭代报告。

## 12. 关键验收标准

- 软件能稳定完成双通道输入、融合、定量、复核和导出。
- 输出中不出现自动确诊或替代医生判断的表述。
- 模型、数据集、阈值和报告模板都可通过配置或适配器替换。
- 大型数据、原始医学影像和 checkpoint 不进入 Git。
- 长期报告归档到 `research/reports/`，运行产物进入 `artifacts/` 或本地临时目录。
- 在没有真实术中样本时，AI 模块只作为原型能力展示，不承诺临床级性能。
