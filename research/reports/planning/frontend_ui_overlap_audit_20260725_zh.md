# Vue 3 临床工程工作站 UI 与功能重叠审计

> 日期：2026-07-25  
> 范围：`frontend/src/`、`frontend/tests/`、10 个桌面端路由  
> 目标：保持业务流程、API、Pinia 数据和路由稳定，统一临床工程工作站的信息架构与视觉层级。

## 2. 信息架构结论

10 个路由全部保留，菜单由类型化导航元数据统一生成：

1. 病例工作流：数据准入、病例档案、病例工作台、三维导航、医生复核、报告导出。
2. 数据与标注：视频库、静态数据复核、人工标注。
3. 三维与展示：工程展示。

应用壳层采用原版桌面顶部导航和主内容区，10 个路由维持既定顺序与 active 状态。主题继续写入原有主题偏好键，病例数据未混入 UI 偏好。项目不设置移动端布局与移动端验收，仅维护 1440、1280、1024 三档桌面/工作站宽度。

## 3. 功能重叠审计

| 区域 | 重叠表现 | 保留职责 | 收敛结果 |
|---|---|---|---|
| `/cases` 与 `/case` | 均展示当前病例和加载反馈 | 病例生命周期管理；病例输入、分析与视频工作台 | 共享页面壳层、病例上下文和反馈语义 |
| `/review` 与 `/annotations` | 均含复核身份、病例状态和编辑反馈 | 候选区/ROI 复核；像素级标注与版本审计 | 保留两套业务编辑器，共享病例上下文和状态样式 |
| `/dataset-review` 与 `/review` | 均含筛选、元数据、空态和复核操作 | 公开静态数据复核；病例运行结果复核 | 共享工具栏、指标摘要和反馈条，数据服务保持隔离 |
| `/intake` 与 `/data` | 均含文件列表、筛选和导入操作 | 医院真实数据准入治理；公开代理视频筛选与导入 | 归入相邻导航层级，统一工具栏和状态语言 |
| `/report` 与工作台导出面板 | 两处均曾展示完整文件明细 | 完整证据包浏览；当前工作台导出摘要 | 文件标签与大小格式化共用，工作台保留摘要、下载和报告入口 |
| `/navigation` 与 `/showcase` | 均展示三维状态和证据边界 | 病例级工程交互；只读工程叙事 | 路由继续独立，共享页面层级和安全边界语言 |
| 病例工作台内部证据面板 | 质量、患者条件、骨活性指标平铺 | 主结果、当前帧和复核证据 | 主分析前置，质量与骨活性证据进入可展开区域 |

审计未发现可以直接删除且不影响业务边界的路由。当前重叠主要位于视觉结构、状态反馈、病例摘要和证据文件格式化层，已通过共享组件收敛。

## 4. 共享 UI 基础

本轮新增并落地：

- `AppPageShell`：页面宽度、密度与主内容边界。
- `AppToolbar`：筛选、字段和操作区布局。
- `AppFeedbackBanner`：处理中、成功、警告和错误语义。
- `AppMetricStrip`：数据摘要与长值换行。
- `AppEmptyState`：统一空态和操作入口。
- `AppCaseContext`：病例标题、长病例号和状态。
- `AppEvidenceArtifactList`：报告页完整证据文件清单。
- `artifactDisplay.ts`：证据类型标签和文件大小格式化。

正文采用 14-15 px，操作标签采用 13-14 px，元数据采用 12-13 px。普通中文使用自然换行；病例号、路径、URL 和哈希使用 `.ov-breakable`。页面、栅格和卡片统一设置 `min-width: 0`，减少长内容撑破布局的风险。

图标统一由 `AppIcon` 与 `appIcons.ts` 管理。本轮补充数据库、筛选、前后导航、信息、外部链接、安全治理和图表图标，并将语义图标覆盖到 10 个路由导航、页面标题、指标摘要、分页命令、元数据展开和来源跳转。普通说明与表单标签保持纯文字，避免装饰性图标影响数据密度。

## 5. 病例工作台层级

病例工作台按以下顺序组织：

1. 病例状态和医生复核边界。
2. 左侧输入、实时视频流控制和分析参数。
3. 主结果摘要、四宫格视频/融合/热图/归一化视口。
4. 当前关键帧、操作与导出摘要。
5. 可展开的质量、患者条件和骨活性证据。

四宫格、MP4 播放同步、连续实时分割、全屏、骨面门控、医生复核和证据导出事件保持原接口。1024 px 桌面宽度下，输入控制与主分析区按单列顺序展开；四宫格仍使用主视频加三项结果的紧凑结构。

## 7. 后续边界

- 后端 API、FastAPI 路由、Pinia 字段、病例 JSON、报告结构和全部 URL 保持稳定。
- 医学安全提示、医生复核状态与非诊断边界保持可见。
- 三维运行时继续独立部署，失效时保留二维证据与复核路径。
- 后续新增页面应从类型化导航元数据和共享组件开始，避免重新复制页面头部、反馈条、空态和证据文件格式化逻辑。
