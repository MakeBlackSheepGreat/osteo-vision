# 医生合作数据需求清单

日期：2026-07-12

现场复核更新：2026-07-15

- 当前合作单位：绵阳市第三人民医院头颈部颌面甲状腺科。
- 现场设备为医院自有设备，与成都赛题方设备分别管理和验证。医院设备可导出 JPG 与 AVI，提供黑白荧光和伪彩显示模式；白光/原彩独立导出能力待医院设备侧确认。医院设备参数不得用于推断赛题方设备能力。
- 近期可采集病例以软组织 ICG 手术为主，颌骨相关病例时间不确定。软组织 ICG 数据用于设备适配、荧光动态、质量控制和医生复核流程验证，按近域工程验证数据登记。
- 医院原始 AVI 应完整保留，项目侧通过受控流程转为 MP4，并记录原始文件 SHA256、编解码参数、转码日志及文件对应关系。

## 1. 目的与当前缺口

本清单用于向口腔颌面外科、感染科、影像科及手术室团队说明项目需要的病例资料、医生复核内容和协作方式。

平台的赛题正式输入边界为企业显微镜导出的 4K JPEG 与 MP4。合作医院设备当前导出 JPG 与 AVI，因此采集端保留设备原始文件，项目端补充受控 AVI 转码后进入 MP4 主流程。当前分层数据注册表已有公开荧光代理视频、公开骨髓炎手术视频、近域论文图和 CBCT 代理数据，但目标域记录数仍为 0。真实脱敏术中白光/ICG 样本、医生关键帧/ROI 标注和病例级临床参照是下一阶段最关键的数据缺口。

本合作数据用于研发验证、比赛方案论证、医生复核辅助和后续模型迭代。平台输出范围为荧光/灌注提示、候选区、边界风险和不确定性提示；临床诊断结论及切除决策由医生独立作出。

### 1.1 软件能力状态

| 能力 | 当前状态 | 医生合作阶段的使用方式 |
|---|---|---|
| 医院批次准入与病例登记 | JPEG/MP4 的 API、CLI 与前端均已实现；AVI 受控转码待实现和验证 | 原始 AVI 先进入受控接收区并保留，转码后的 MP4 与 JPEG 进入现有准入流程，核验授权、脱敏、文件签名、可解码性、SHA256、重复文件、通道关系和同步配对 |
| 4K MP4 上传与关键帧分割 | 已实现工程闭环，待真实目标域验证 | 导入显微镜 MP4 后抽取关键帧，生成概率图、四类 mask、伪彩、叠加图、候选区和分割 manifest |
| 浏览器摄像头单帧与连续分析 | 已实现串行连续推理 | 连接摄像头后可抓取单帧；连续模式默认在上一帧完成后立即抓取下一帧，也可设置 1、2、3、5、10 秒间隔，记录会话编号、序号、采集时间和端到端耗时 |
| MP4 播放连续分析 | 已实现串行连续推理 | MP4 播放时持续抓取当前播放帧，完成一帧推理后继续下一帧，并刷新最近完成帧的叠加、mask、候选区和元数据；离线关键帧分析继续承担可复核证据生成 |
| 医生 mask 编辑与回灌 | 已实现基础闭环，待医生试用 | 支持骨面门控生成、修改、接受、拒绝和复核状态写回 |
| 连续分析性能 | 已记录帧级耗时，待官方显微镜实机基准 | 推理过程采用串行队列，处理节奏由帧传输、模型推理和结果写入耗时共同决定；当前尚无官方显微镜 4K 输入下的稳定帧率和延迟数据 |

以上“已实现”表示前后端工程链路和自动化测试已具备。连续分析会显示最近完成的分割结果，不承诺覆盖原始视频的每个源帧。真实颌骨骨髓炎术中 ICG 数据上的有效性、稳定性、显微镜接入性能和医生可用性仍需本次合作验证。

所有医院准入样本初始状态均为 `review_required`、`label_type=unlabeled`、`training_eligible=false`。文件通过准入只表示来源、交接条件和工程质量门满足要求，医生复核、标签形成和训练准入需要后续独立完成。

## 2. 建议的合作分期

| 阶段 | 医生团队提供或确认的内容 | 目标产出 |
|---|---|---|
| P0：流程试运行 | 4-5 例脱敏病例或可用历史病例资料；每例 5-10 个关键帧的快速复核 | 验证采集格式、双通道关系、标注词表、关键帧工作流 |
| P1：小金标准集 | 从 P0 中选取约 20-50 帧；医生完成 ROI、复核状态和临床语义标记 | 形成首批医生复核的小金标准候选集 |
| P2：连续积累 | 新增病例、术中视频、CBCT 和术后参照；对高优先级帧进行回填 | 支持目标域适配、独立评估和失败样本分析 |

P0 的数据量用于工程流程验证和标注规范校准。模型临床性能评价需在后续扩大病例量、完成独立验证和机构确认后开展。

## 3. 每例病例的核心数据包

### 3.1 术中显微镜影像

| 优先级 | 需要的数据 | 具体要求 |
|---|---|---|
| P0 | 设备原始 AVI | 合作医院设备原生导出文件，禁止预先压缩或改格式；项目侧保留原始文件并受控转码为 MP4 |
| P0 | 原始 4K MP4 | 保留原始码率、分辨率、帧率和文件创建时间；文件名使用脱敏 `case_id` |
| P0 | 术中 JPEG | 白光、荧光、伪彩叠加图如能分别导出则分别保留 |
| P0 | 通道关系说明 | 记录白光、荧光、叠加图的输出模式；如为模式切换视频，记录各段的起止时间；如为同步双通道，保留时间戳或帧号对应关系 |
| P0 | 关键术中阶段 | 标注清创前、ICG 显影过程、清创中、清创后和医生认为有边界意义的阶段 |
| P1 | 视频质量信息 | 标记烟雾、出血、器械遮挡、强反光、失焦、过曝、欠曝、镜头移动和无法判读画面 |

如设备可导出白光、荧光和叠加三类内容，建议每类文件均保留。设备只导出单一混合视频时，需保留该原始文件并记录显示规则，不对双通道同步关系作推断。

### 3.1.1 合作医院首批试采协议

1. 首例先作为兼容性试采。项目侧完成 AVI 解码、转码、关键帧与模式确认后，再扩展至 4-5 例。
2. 连续主视频优先使用黑白荧光模式，从 ICG 给药前 15-30 秒开始，连续记录给药后至少 3 分钟；条件允许时延长至 5 分钟。
3. 荧光信号稳定或达到医生认为的重要阶段时，同一术野补录 30-60 秒伪彩视频。
4. 同一术野在给药前、首次显影、显影较强阶段和给药后 2-3 分钟分别保存 JPG；每个时间点优先保留黑白荧光和伪彩，设备若支持白光/原彩则同步补充。
5. 构图同时覆盖手术目标、邻近正常参照组织、荧光强弱过渡区。临床条件允许时保持视野、倍率、焦距、曝光与增益稳定。
6. 每例由医生指出 3-5 个关键时间点，并用简短文字说明目标组织、参照组织、荧光表现和临床关注点。
7. 软组织病例按设备与荧光动态工程验证数据登记。颌骨病例出现后沿用同一协议，并增加暴露骨面、疑似异常骨边界、处理前后和医生最终判断记录。

### 3.2 采集与显影元数据

每个影像文件建议附带以下字段。缺失字段可留空，保留缺失原因。

| 字段 | 医生或手术室团队可提供的内容 |
|---|---|
| `case_id` | 脱敏病例编号 |
| `device` / `device_resolution` | 显微镜型号、采集分辨率、视频或图像格式 |
| `acquisition_mode` | 白光、荧光、叠加、模式切换或同步双通道 |
| `acquisition_time` | 采集时间或相对手术时间 |
| `icg_dose` / `icg_route` | ICG 剂量、给药途径；按医院记录口径提供 |
| `icg_time_sec` | 给药后至采集时的秒数；未知时留空 |
| `magnification` / `working_distance` | 可获得时记录倍率和工作距离 |
| `exposure` / `gain` / `illumination` | 可由设备导出时保留 |
| `operator_note` | 术野状态、异常事件、清创步骤和医生备注 |

### 3.3 临床参照信息

医生团队可在允许范围内提供以下脱敏摘要，帮助建立可复核的病例级证据链：

- 病变部位：上颌、下颌、牙区、侧别和范围描述。
- 临床背景：骨髓炎类型、病程、既往治疗、手术指征和主要症状。
- 术中判断：活骨、疑似坏死骨、炎症组织、保留区、边界风险区和无法判定区。
- 清创范围及医生最终处理意见。
- 术后病理、微生物培养、组织学或随访结果；仅在医院允许并完成脱敏后关联。
- 术前 CBCT/CT：优先 DICOM 或 NIfTI 及必要的影像学结论；保留体素间距、方向和检查日期的脱敏版本。

## 4. 医生需要完成的复核任务

平台会先自动抽取关键帧、生成候选区和主动复核队列。医生重点处理高价值帧，减少逐帧检查负担。

| 任务 | 医生操作 | 平台记录 |
|---|---|---|
| 关键帧确认 | 选出有临床意义、图像质量可用或存在风险的帧 | `frame_index`、`timestamp_sec`、优先级 |
| 骨面门控 | 圈画暴露骨面或疑似骨面范围 | `bone_gate_mask` |
| 软组织与遮挡 | 标出软组织、器械、烟雾、血液、反光等影响判读的区域 | `soft_tissue_mask`、`occlusion_mask` |
| 荧光/灌注信号 | 标出高荧光候选、骨面内低荧光或低灌注候选 | `fluorescence_signal_mask`、`hypo_fluorescent_bone_mask` |
| 边界风险 | 标出建议重点复核的过渡区，并给出简短原因 | `risk_mask`、`review_notes` |
| 不确定性 | 标出当前无法可靠判读的区域和原因 | `uncertain_mask`、`failure_reason` |
| AI 结果复核 | 接受、修改、拒绝或保留待复核 | `accepted`、`modified`、`rejected`、`review_required` |

医生复核后的 `accepted` 和 `modified` 样本可作为高权重训练候选；`rejected` 样本进入错误分析或负例候选；`review_required` 样本保留在队列中。所有标签继续保留病例来源、复核人角色、复核时间和修改痕迹。

## 5. 建议的标注粒度

1. 每例先复核 5-10 个关键帧，覆盖显影动态和主要清创步骤。
2. 每帧先给出可用性、骨面 ROI、临床风险类别和复核状态。
3. 从高不确定性、时序跳变、候选区面积异常的帧中优先挑选 20-50 帧完成精细 mask 修改。
4. 抽取一部分帧由两名医生独立复核，保留分歧、讨论结论和最终共识，用于评估标注一致性。
5. 病理、培养或随访结果可作为病例级参照字段；术中单帧掩码与病理切片之间的空间对应关系需单独记录，缺少对应关系时不建立像素级因果关联。

| 口腔颌面外科主刀或高年资医生 | 确认术中阶段、骨面范围、边界风险、清创处理和复核结论 |
| 影像科或口腔放射医生 | 复核 CBCT/CT 的病变范围、解剖风险结构和影像质量 |

| 科研协调员 | 完成伦理资料、脱敏、文件编号、数据交接和访问记录 |

## 7. 数据脱敏、伦理与交接

- 在数据导出前移除姓名、住院号、身份证号、电话号码、精确出生日期、面部信息、语音、屏幕叠字和可识别的 DICOM 标签。
- 建立 `case_id` 映射表并由医院保管；项目侧仅接收脱敏编号。
- 在病例采集或使用前，由合作医院完成伦理审查、知情同意或其他经机构确认的数据使用依据。
- 若涉及组织、血液、遗传或其他额外敏感材料，由医院科研管理部门另行确认适用要求。
- 原始病例影像、DICOM、视频和关联表仅存放于受控本地数据目录或医院认可的受控环境，不进入 Git 仓库，不通过公开网盘传播。
- 每次交接保留来源、文件 SHA256、用途范围、接收人、日期和授权状态。

### 7.1 当前批次准入流程

1. 医院团队先完成伦理或机构授权确认、脱敏检查，并保管脱敏病例编号与院内身份的映射表。
2. 项目团队将 JPEG/MP4 放入平台受控数据目录，通过“医院数据准入”页面上传，或编写 UTF-8 JSON manifest 后调用命令行入口。
3. 平台逐文件检查官方格式、内容签名、解码状态、SHA256、历史重复、病例编号、采集通道和同步配对完整性。
4. `admitted` 文件写入受控病例档案，可进入工程分析与医生复核；`quarantined` 文件保留原因码，不写入平台病例输入。
5. 每批生成 `hospital_intake_report.json`、`hospital_intake_records.csv` 与 `hospital_intake_artifact_status.json`。项目团队需先处理隔离原因和病例附件挂接异常，再开展关键帧分析或医生标注。

命令行入口复用平台医院准入服务，manifest 内的相对文件路径以 manifest 所在目录为基准：

```powershell
conda activate osteo-vision
python tools/admit_hospital_data_batch.py `
  --manifest C:\hospital_handover\controlled\batch_001.json `
  --artifact-root C:\hospital_handover\controlled `
  --case-store C:\hospital_handover\controlled\cases.sqlite
```

`--artifact-root` 是本次准入的受控根目录，manifest 引用的 JPEG/MP4 必须位于该目录内。命令会在标准输出返回 JSON，明确列出准入数量、隔离数量、病例编号、病例库路径、JSON/CSV 报告路径，以及完整 `artifact_attachment` 状态，其中包含状态文件路径、预期病例数、已挂接病例数和失败详情。退出码为：`0` 批次报告与病例登记完成、`2` manifest 无效、`3` 批次编号冲突、`4` 处理失败。

病例附件挂接异常时，命令顶层 `status` 与 `artifact_attachment.status` 均为 `completed_with_errors`，退出码保持 `0`。这表示准入报告和病例登记已经完成，项目团队仍需依据 `hospital_intake_artifact_status.json` 的失败项补做附件挂接并复核病例证据链。

最小 manifest 示例：

```json
{
  "batch_id": "hospital-batch-001",
  "handover_id": "handover-20260713-001",
  "source_organization": "合作医院A",
  "received_by": "project_receiver",
  "received_at": "2026-07-13T09:00:00+08:00",
  "authorization_status": "approved",
  "usage_scope": "competition_research_validation",
  "deidentification_confirmed": true,
  "deidentification_method": "hospital_export_review",
  "mapping_held_by_institution": true,
  "target_condition_confirmed": true,
  "files": [
    {
      "external_case_id": "HOSP_CASE_001",
      "path": "case_001_white.jpg",
      "channel": "white_light",
      "acquisition_mode": "white_light",
      "channel_relationship": "single_channel",
      "metadata": {
        "device": "official_microscope",
        "icg_time_sec": 30,
        "exposure": "locked",
        "gain": "locked",
        "illumination": "locked"
      }
    }

}
```

同步白光/荧光 JPEG 需各写一条文件记录，两条记录使用同一 `external_case_id` 和 `pair_id`，并设置 `channel_relationship=synchronized_pair`。MP4 使用 `channel=video`，同时记录实际 `acquisition_mode` 和通道关系。`target_condition_confirmed` 仅在医院已确认病例符合本项目目标疾病范围时填写 `true`，诊断或纳入状态待确认时填写 `false`。授权状态未批准、脱敏未确认、映射表未由医院保管、文件越出受控目录、格式或签名不匹配、同步配对不完整、跨批次重复等情况会进入隔离。

## 8. 项目团队承担的工作

- 提供脱敏文件命名约定、JSON manifest 示例、医院数据准入页面和命令行导入工具。
- 自动完成 JPEG/MP4 签名与解码校验、SHA256、批次内及历史重复检查、隔离原因记录、病例登记、JSON/CSV 准入报告和病例附件挂接状态记录。
- 自动完成视频关键帧抽取、质量初筛、候选区预标注和主动复核排序；摄像头与 MP4 连续分析采用串行推理，默认在上一帧完成后立即继续，并保留开始、停止和可选间隔控制。
- 提供可视化标注工作台，支持画笔、擦除、接受、修改、拒绝、备注和版本留痕。
- 将医生复核结果转为可追溯训练 manifest，并保留样本权重、复核状态和数据域标签；准入后尚未复核的医院样本保持训练禁入。
- 输出病例级可视化、量化结果和研发验证报告，持续保留医生复核与非诊断边界。

## 9. 首次沟通时可直接确认的十个问题

1. 是否存在可导出的白光、荧光或叠加术中 MP4/JPEG，导出方式和权限如何？
2. 现有设备能够输出哪些模式，白光与荧光之间是否带有时间戳或帧号关系？
3. ICG 给药、显影和采集时间能否从麻醉记录、手术记录或设备日志中取得？

## 11. 本清单的项目依据

- 官方赛题原文：要求覆盖新型荧光造影剂设计、多模态白光/荧光图像获取配准融合、AI 辅助显微成像判读，并要求方案具备与企业荧光手术显微镜系统集成的可行性。
- 官方设备技术文档：输入优先级为 3840x2160 的 JPEG 与 MP4；ICG 在约 750-810 nm 激发、约 830 nm 发射，具有动态灌注信号属性。
- `configs/tasks/osteo_vision.yml`：已定义医生复核相关的 `bone_gate_mask`、`fluorescence_signal_mask`、`risk_mask`、`uncertain_mask`、`review_state` 和样本权重契约。
- `research/reports/modeling/video_active_review_queue_20260711_zh.md`：已实现关键帧主动复核队列、复核状态回填和训练 manifest 补丁。
- `research/reports/modeling/layered_dataset_registry_quality_20260711_zh.md`：当前目标域记录数为 0，医生复核目标域样本是后续数据闭环的关键输入。
- `backend/src/services/hospital_intake_service.py`：医院批次授权、脱敏、文件质量、SHA256、重复、配对、隔离、病例登记与报告生成的统一准入服务。
- `tools/admit_hospital_data_batch.py`：从本地 UTF-8 JSON manifest 调用统一准入服务的命令行入口。
- `backend/src/services/live_frame_service.py` 与 `frontend/src/composables/useContinuousCameraAnalysis.ts`：摄像头和 MP4 播放帧的串行连续推理、会话与帧级耗时记录入口。
