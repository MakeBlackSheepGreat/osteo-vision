# 三项优先能力数据契约、标注 SOP 与验收协议 v1

版本：1.1.0
生效日期：2026-07-19
状态：工程冻结基线，阈值待仿体实验、目标域样本和医生复核确认

## 1. 适用范围与项目能力映射

本协议用于验收患者条件分割、骨活性连续谱、倍率/工作距离感知的三维配准与导航验证。三项能力用于完善平台的多模态图像处理和 AI 辅助判读链路。造影剂研究作为独立资料维护，不由本协议替代。

所有结果均为研发验证证据。空间边界、骨活性类别和导航状态必须保留医生复核、失败闭合和不可声称范围。

## 2. 共同数据治理

每个输入和派生产物至少记录：

- `case_id`、`input_id`、`analysis_run_id`、`device_source`。
- 来源机构、用途授权、脱敏确认、接收时间、文件 SHA256。
- 原始尺寸、格式、采集时间、通道角色、同步状态和质量标记。
- 算法、配置、模型、阈值、代码版本、生成时间和上游证据路径。
- 医生身份、机构、认证来源、复核状态、复核时间和版本历史。
- 数据域、许可状态、训练准入状态及不可声称范围。

公开、代理、伪标注和异域数据默认 `training_eligible=false`。只有完成许可复核、质量复核、来源分组和任务准入后，才可进入对应工程或训练清单。

项目侧持续主动检索、下载和校验三项目标所需的公开、代理和近似数据，不等待企业设备接口或企业数据。每项资源至少记录来源页面、直接下载地址、许可、数据域、患者或样本数量、模态、标签、临床变量、用途、本地路径、文件大小、SHA256、下载时间和用途边界。无法确认许可、治理状态或患者级拆分的数据只能进入候选清单。

## 3. 三路显微影像契约

### 3.1 通道角色

- `raw_color`：原彩图或独立白光图，作为几何、组织外观和模型输入证据。
- `raw_fluorescence`：原始荧光图，作为荧光定量、伪彩、融合和模型输入证据。
- `device_overlay`：设备生成的叠加图，用于医生显示、设备质控和证据核对。

`device_overlay` 不得作为独立真值或默认训练标签。无法确认叠加算法、原始性或几何关系时，只能保留为显示证据。

### 3.2 必填或建议字段

- `device_source`、设备型号、固件版本、采集配置。
- 通道角色、文件名、分辨率、像素格式、帧时间戳。
- 曝光、增益、倍率、工作距离及其来源。
- 通道同步状态、时间差、几何关系和配准状态。
- 原始文件 SHA256、转码关系和处理日志。

### 3.3 安全降级

- 缺少 `raw_color`：暂停依赖白光外观或白光—荧光配准的能力。
- 缺少 `raw_fluorescence`：暂停荧光定量、活性评分和荧光候选输出。
- 仅有 `device_overlay`：允许播放和证据查看，禁止反解定量或生成训练真值。
- 时间、尺寸或几何不一致：输出明确原因码，暂停融合空间结论。

## 4. 患者临床变量契约 v1

### 4.1 字段

- 人口学：`age_years`、`sex_at_birth`。
- 基础病：规范名称、编码、活动状态和记录时间。
- 用药：通用名、剂量、给药途径、开始/停止时间及与采集的相对时间窗。
- 化验：指标名、数值、单位、参考范围、采样时间、异常标记。
- 首批指标：CRP、WBC、ESR、PCT、白蛋白、血糖、HbA1c、肌酐。
- 治理：脱敏确认、记录来源、复核状态、可信复核人、机构、认证来源、复核时间。

年龄由影像采集日期与出生日期计算；只保留年龄值时必须记录计算或录入来源。化验值进入评估前统一到规范单位，同时保留原值、原单位和转换规则。医院参考范围优先于平台通用参考范围。

### 4.2 状态与门控

- `unreviewed`：尚未人工复核。
- `review_required`：已保存，仍需可信医生或项目复核者核验。
- `verified`：可信身份已核验，复核证据完整。

普通工程会话不能提交 `verified`。无效 Bearer 凭证必须明确失败。缺失、过期、未来时间、单位不支持、脱敏未确认、未复核或分布外数据均触发影像基础结果回退。

### 4.3 输出契约

- `image_only_mask`、`image_only_probability`。
- `conditioned_mask`、`conditioned_probability`，未获准时保持不可用。
- `difference_mask`、差异面积和最大边界位移。
- 特征版本、缺失值掩码、上下文校验码、质量问题和影响摘要。
- `spatial_effect_applied`、`fallback_reason_codes`、校准证据。

### 4.4 v1 验收

- 未认证会话请求 `verified` 时，API 返回安全拒绝或强制保持 `review_required`，不得形成已核验记录。
- 可信身份提交 `verified` 时，身份、机构、认证来源和 UTC 时间完整持久化。
- 每种缺失、单位、时效、脱敏和复核异常均有机器可读原因码。
- 当前生产主线保持 `spatial_effect_applied=false`，影像空间边界不随规则摘要变化。
- 未来启用条件模型前，必须完成患者级、机构级、时间级独立验证、概率校准和年龄/性别/基础病亚组审计。
- 条件结果相对基础结果的允许差异、边界位移和安全回退阈值由目标域验证确定，并写入后续协议小版本。

## 5. 骨活性标注词典与医生 SOP v1

### 5.1 标签词典

- `bone_gate`：医生确认可评估的暴露骨面。
- `low_activity_candidate`：荧光或灌注活性偏低、需重点复核的候选区。
- `transition_candidate`：信号、颜色、纹理或医生意见处于边界状态的复核区。
- `high_activity_reference`：在当前证据下活性相对较高、可供对照的参考区。
- `ignore`：遮挡、反光、焦外、污染、器械覆盖、信号饱和、证据冲突或无法判断区。

上述标签表达术中信号与复核优先级，不能直接等同病理坏死、手术切缘或可保留结论。

### 5.2 标注步骤

1. 记录原彩图、原始荧光图、设备叠加图及同步、曝光、倍率、工作距离信息。
2. 医生先标注 `bone_gate` 和 `ignore`，不得先看模型三类结果形成锚定偏差。
3. 在可信骨面内独立标注低活性、过渡、高活性区域；允许区域互斥并记录分歧边界。
4. 记录取样点、标本方向、切缘、离体照片、病理编号和回映射可信度；暂缺字段保持空值和原因码。
5. 第二位医生独立复核。分歧区域保留原始版本，并由第三位医生或专题会议仲裁。
6. `accepted`、`modified` 进入高权重复核清单；`rejected` 进入负例或错误分析清单；工程草稿保持独立来源。

### 5.3 输出与验收

- 无可信 `bone_gate` 时，三类空间 mask、面积占比和分类图保持不可用。
- 有可信 `bone_gate` 时，所有空间候选必须位于骨面范围内，并保留骨面版本和审核人。
- 连续评分、分类阈值、不确定性和校准状态进入 JSON、报告和证据包。
- `0.80` 只能在指标定义清楚且经过校准时表述为候选置信度或目标覆盖率。
- 多医生标注需记录 Dice/IoU、边界距离、类别混淆和分歧区占比；阈值由目标域小金标准集确认。

## 6. L0/L1/L2 三维配准契约 v1

### 6.1 坐标与变换

每个坐标系使用唯一名称，并记录右手系/左手系、长度单位、轴方向和来源。每条变换记录：

- `source_frame`、`target_frame`、`direction`、`unit`。
- 文件路径、SHA256、格式、4×4 矩阵、生成方法和时间。
- 有限值、末行、行列约定、可逆性和条件数检查。
- 坐标链连续性及逆变换关系。

支持格式由实现白名单管理。文件缺失、校验失败、非有限值、不可逆、方向冲突、单位冲突或坐标链断裂均触发 L0。

### 6.2 标定和显微镜元数据

- 内参、畸变、图像尺寸、标定日期、标定方法和重投影误差。
- 倍率与工作距离的有效范围、标定项、选择方法，以及经过独立批准后才可启用的插值方法。
- 当前倍率、当前工作距离、来源和时间戳。
- 位姿跟踪、视频帧时间戳和同步误差。
- 基于视频 PTS 的倍率变化率、工作距离变化率、内参切换率、标定候选歧义和 `A/B/A` 内参振荡。

倍率或工作距离超出标定范围时，暂停空间叠加。L1 静态验证只允许 SHA256 绑定的版本化 registration manifest，并绑定病例、可解析模型、点对 artifact、坐标空间、单位和变换方向；人工录入及文件元数据只进入 L0 静态几何或 pose-only 工程检查。strict dynamic AR 的安全关键元数据只允许来自 SHA256 绑定 manifest 和病例持久化 L1 证据。

### 6.3 误差证据

- 刚性配准记录 FRE。
- 使用独立目标点记录 TRE。
- 图像投影记录重投影误差。
- 动态回放记录漂移、同步误差和跟踪丢失。
- 每个阈值记录来源、仿体协议、数据版本、批准人和批准时间。

未经仿体和医生/工程复核确认的数值不能开启导航就绪。固定阈值将在仿体验证后写入 v1.x。

### 6.4 L2 受控 manifest 与视频证据

`dynamic_ar_validation` 请求只允许携带病例 ID、回放模式、`offline_manifest` 输入模式、manifest 路径及 SHA256、病例视频输入 ID 和医生复核状态。逐帧 pose、三维投影点、相机内参标识、失效注入、九项安全参数和批准快照不得由客户端独立覆盖。

SHA256 绑定 manifest 至少包含：

- 病例 ID、已准入 MP4 的输入 ID、视频 SHA256 和视频帧数。
- L1 内参标识、`calibration_table_id`、三维投影点及坐标空间、逐帧 pose、倍率、工作距离和跟踪状态。
- 每帧显式 `tracking_drift_mm` 与独立来源、`dynamic_target_error_mm` 与独立来源。
- 独立漂移/DTE 测量 artifact 的路径、SHA256、版本、病例/视频绑定、逐帧记录、复核身份和时间。
- `max_time_offset_ms`、`drift_threshold_mm`、`tre_proxy_threshold_mm`、`dynamic_target_error_threshold_mm`、`minimum_visible_projection_points`、`max_magnification_rate_per_s`、`max_working_distance_rate_mm_per_s`、`max_intrinsics_switch_rate_hz` 和 `calibration_ambiguity_margin` 九项安全参数。
- `osteo-vision-l2-threshold-policy-v2` 策略 artifact 的路径、SHA256、策略版本、协议版本、数据版本、批准人、批准时间和九项参数快照；批准值只能保持或收紧平台安全边界。
- 医生复核状态。`accepted` 必须绑定可信 physician 身份、机构、认证来源和复核时间。

平台必须从病例持久化证据读取完整 L1 PnP/相机标定、CBCT 到相机变换、独立 TRE、独立重投影误差、标定文件 SHA256、标定范围及 L1 阈值批准。相机标定 artifact 必须使用 `osteo-vision-camera-calibration-v2`，包含唯一表 ID、`nearest_validated_entry_v1` 策略和至少一个独立验证的倍率/工作距离内参项。平台逐帧选择覆盖当前倍率/工作距离且归一化距离最近的标定项，并记录表 ID、选择方法和所选内参 ID。客户端提交的 L1 安全证据不得覆盖病例记录。

平台使用 FFprobe 提取实际 MP4 的逐帧 PTS；PTS 缺失、非严格递增、帧数不一致或视频/manifest 的输入 ID、SHA256、帧数不一致时触发 L0。视频在解码和 overlay 前后均复核 SHA256，输出 FPS 从已验证 PTS 中位间隔推导并复核帧数、PTS、恒定间隔和时长。当前 L2 只允许已验证恒定帧率视频；识别到 VFR 时输出 `video_variable_frame_rate_unsupported`、回退 L0 且不生成 overlay。每帧必须完成内参项选择、`3D -> 2D` 投影、正深度、画幅内可见点、时间偏移、显式漂移和独立动态目标误差检查。倍率变化率和工作距离变化率必须使用相邻 FFprobe PTS 计算；标定候选归一化距离差落入歧义裕量、内参切换率超限或出现 `A/B/A` 振荡时，整次回放失败闭合。

### 6.5 级别验收

- L0：允许 CBCT/STL 与二维候选并列查看；`navigation_ready=false`。
- L1：变换、标定范围、静态位姿、独立误差、阈值来源和医生复核全部通过；标记为静态/仿体配准验证。
- pose-only：只用于位姿链、同步和失效注入工程检查，永久输出 L0，不能生成可用 AR 叠加。
- L2：在完整已验证 L1 基础上，v2 多点标定表绑定及逐帧最近项选择、已准入恒定帧率 MP4、FFprobe PTS、受控 manifest、逐帧投影、可见性、显式漂移、独立动态误差、时序连续性、九项安全参数批准、可信医生复核及 overlay SHA256 全部通过；只标记为离线动态 AR 工程验证。

全部门控通过时输出逐帧 CSV、回放 manifest、overlay MP4 及 SHA256，并持久化 `three_d_ar_overlay`。任一必需证据失效时立即删除或隐藏 overlay，撤销旧 L2 active 引用，恢复可信 L1 snapshot，记录机器可读原因并回退 L0。取消任务保持零病例持久化。

## 7. 失效注入清单

- 临床上下文：缺失值、错误单位、过期值、未来时间、未脱敏、未复核、无效身份、分布外输入。
- 骨活性：骨面缺失、骨面未复核、遮挡、反光、饱和、全空 mask、过分割、类别冲突、阈值缺失。
- 三路影像：帧错配、尺寸不一致、时间差超限、通道角色错误、仅设备叠加图。
- 三维配准：变换或标定文件缺失、SHA256 错误、矩阵损坏、不可逆、单位/方向错误、坐标链断裂、倍率/距离越界、独立 TRE/重投影误差缺失或超限、L1 阈值批准缺失。
- L2 动态回放：pose-only 申请导航、未准入 MP4、视频 SHA/ID/帧数不匹配、FFprobe PTS 缺失或不递增、VFR、v2 标定 artifact/表 ID/选择策略/标定项缺失或失配、倍率/距离无覆盖项、倍率或工作距离变化率超限、内参切换率超限、标定选择歧义、`A/B/A` 内参振荡、manifest 被篡改、客户端覆盖安全字段、投影点缺失、正深度或可见点不足、时间偏移超限、显式漂移/独立动态误差缺失或超限、位姿丢失、视频跳帧、L2 安全策略批准失配、可信医生复核缺失、overlay 帧数或 SHA256 异常。

每项失效注入必须验证：机器可读原因码、医生可读提示、空间能力撤销、证据日志和恢复路径。

## 8. 完成定义

本协议 v1 软件闭环完成需同时满足：

- 后端契约、持久化、身份门控、严格配置和失败闭合测试通过。
- 前端可对照查看临床上下文、骨活性证据和 L0/L1/L2 安全状态。
- 报告和证据包保留基础结果、候选结果、差异、复核、阈值来源和降级原因。
- 公开/代理数据 manifest 完整，来源、许可、样本、模态、标签、临床变量、用途、本地路径、大小、SHA256、下载时间和用途边界通过机器或人工复核，训练准入边界明确。
- 模型重训练继续保持最后阶段，且晋级需通过独立测试、校准、亚组审计、性能和严格运行门控。
- 目标域晋级指标必须从 checkpoint 绑定的逐病例预测资产和医生复核真值独立重算；聚合指标自报、资产缺失、哈希篡改、病例/患者/split 不一致均失败闭合。
- 运行替换必须同时具有可信医生和项目复核员的独立 Ed25519 签名；签名需绑定模型 ID、checkpoint、已批准策略和完整证据包哈希，并通过认证身份、密钥状态、防重放、撤销、追加式哈希链和最终 bundle 重放。生产策略哈希或公钥信任表为空时保持关闭。

严格 L2 软件闭环的既有聚焦回归基线为后端相关 67 项通过，Black 与 Ruff 通过；前端 9 项和类型检查通过。时序连续性扩展另有核心与工具单测 44 项、后端合同 22 项、前端 6 项通过，并通过 Vue 类型检查、Ruff、Black 和聚焦 mypy。上述基线只覆盖软件契约、受控证据和失败闭合；真实设备全倍率/全工作距离 4K 多点标定、真实下颌仿体物理精度、独立动态测量阈值和真实术中空间导航需在后续验收版本单独记录。
