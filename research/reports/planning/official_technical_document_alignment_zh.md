## 2. 对软件最关键的官方设备参数

官方技术文档明确了以下输入相关参数：

| 模块 | 官方参数 | 对软件设计的影响 |
|---|---|---|
| 4K 影像系统 | 分辨率 3840x2160 | 前端预览、后端上传、视频解码和关键帧抽取必须按 4K 输入设计，不能只按普通小图 demo 设计。 |
| 影像存储 | USB3.0 影像存储 | 比赛版优先支持本地文件上传和证据包导出，不把实时设备 SDK 作为第一阶段硬依赖。 |
| 图片格式 | JPEG | 图片上传入口必须接受 `.jpg` / `.jpeg`，并保留设备来源、分辨率和采集时间等元数据。 |
| 视频格式 | MP4 | 视频上传入口必须接受 `.mp4`；系统应支持视频基本质控、关键帧抽取、帧级 ROI 和报告留证。 |
| ICG 激发/发射 | 激发约 750-810 nm，发射约 830 nm | ICG 通道应定位为近红外荧光信号；报告中避免把 ICG 说成骨髓炎特异性探针。 |
| 临床原理 | 血管显影、血流动态评估、部分肿瘤边界识别 | 本项目可迁移为灌注/组织活性参考和边界风险提示，不应宣称自动确诊。 |

## 3. 系统输入优先级

比赛版输入优先级应调整为：

1. 官方设备导出的 4K MP4 视频上传。
2. 官方设备实时视频流预览或短片段采集。
3. 官方设备 JPEG 图片上传。
4. 白光/ICG 双通道单帧图片。
5. 同步帧序列。
6. 研究扩展输入：CBCT/CT/DICOM/NIfTI、公开数据集缓存、标注掩码。

这意味着前端第一屏不能只像普通医学影像上传器，而应突出“视频/图片来自手术显微镜”的工作流。

## 4. 推荐的软件处理链路

官方设备输入进入软件后的主链路建议固定为：

1. **输入接收**：MP4/JPEG 上传、视频流预览、文件大小和分辨率检测。
2. **视频质控**：读取帧率、帧数、时长、分辨率、过曝/欠曝、模糊和荧光弱信号提示。
3. **关键帧抽取**：支持按时间点、荧光强度峰值、医生手动选择或均匀采样抽帧。
4. **白光/ICG 分析**：伪彩、热图、叠加、归一化、阈值掩码和 ROI 定量。
5. **AI 辅助判读**：以关键帧或帧序列为输入，输出候选区域、边界风险和不确定性提示。
6. **医生复核**：医生接受、修改、驳回或标记需要复查。
7. **证据输出**：关键截图、结构化 JSON、量化 CSV、Markdown/PDF 报告和后续 DICOM 扩展。

## 5. 与当前项目的工程对齐

本轮已将官方输入约束落入以下工程位置：

- `AGENTS.md`：写入官方 4K MP4/JPEG 输入边界。
- `configs/tasks/osteo_vision.yml`：任务契约增加 `video_file`、`video_stream` 和官方设备参数。
- `configs/inference/osteo_vision.yml`：推理配置增加 `.mp4`、官方 4K 分辨率和流式输入 scheme。
- `src/io/video_io.py`：新增 MP4 视频元数据读取。
- `src/preprocess/input_validation.py`：新增 `video_file` 输入识别与元数据摘要。

## 6. 下一步实现重点

近期不应继续泛泛扩展格式或模型名，应该优先补齐与官方文档直接相关的功能：

1. 前端上传区增加“4K MP4 / JPEG 来自手术显微镜”的明确入口。
2. 后端上传服务接受 MP4，并返回分辨率、帧率、时长、帧数等元数据。
3. 新增视频关键帧抽取服务，先支持均匀采样和医生指定时间点。
4. 将关键帧接入现有荧光融合、ROI 定量和报告输出。
5. 报告模板增加“官方设备输入摘要”和“ICG 医学边界说明”。

医学边界：本系统输出仍为研究和比赛原型结果，只能作为术中参考、风险提示和医生复核辅助，不能替代临床诊断或治疗决策。
